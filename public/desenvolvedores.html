Contrato dos dados

data contém date, period, value numérico e rawValue original. Em meta estão o indicador, unidade, produtor, fonte consultada, horário de coleta, cobertura e corte do resultado.

Períodos: YYYY-MM-DD para séries diárias, YYYY-MM para mensais e YYYY-QN para trimestrais. date preserva a data de referência original em ISO; não é data de publicação.

Metadados incluem explanation: o que mede, para que serve, como ler e cuidados. Poupança tem frequência diária e unidade mensal: frequência não determina a unidade.

Consultas e erros

start e end: datas inclusivas YYYY-MM-DD, sem futuro, até cinco anos por consulta. Padrão: um ano para diárias e cinco para as demais. limit: 1 a 2.000 (padrão 60); retorna as últimas N observações em ordem crescente.

meta.truncated indica corte. Intervalo vazio retorna data: [] e status: "empty". Erros têm { error: { code, message } } e status HTTP apropriado. Não converta erro ou ausência em zero.

CSV usa UTF-8, vírgula e ponto decimal, com unidade e proveniência em cada linha.

MCP sem chatbot

Endpoint /api/mcp, transporte Streamable HTTP, SDK oficial. Ferramentas de leitura: search_indicators, get_indicator e get_observations.

Sem sessões, SSE ou notificações iniciadas pelo servidor. GET e DELETE retornam 405. Clientes devem aceitar JSON e event-stream conforme o protocolo. A configuração acima é para VS Code; outros clientes podem usar outro formato.

Limites operacionais

Cache em memória de cinco minutos e até 100 intervalos por instância; pode desaparecer em cold starts. Timeout de vinte segundos na fonte. Sem SLA, autenticação ou rate limiting distribuído.

O deploy usa Vercel, sem depender de Cloudflare ou Turso. Cache compartilhado e armazenamento persistente são evoluções possíveis, não serviços já provisionados. Dados podem ser revisados pela fonte; não há arquivo de revisões.
